# Private payment receipt service

Deploy this directory into its own Apps Script project, never the public gallery project. Set `RECEIPTS_ROOT_ID` to a directly owner-only Drive folder outside the gallery hierarchy and `RECEIPTS_HMAC_SECRET` to an independently generated server key of at least 32 characters in **Script Properties**. Keep both out of source and browser URLs. The manifest activates the built-in Drive v3 service (automatically enables its API for a default Apps Script Cloud project) and requires Drive/external-request owner consent.

Publish a **versioned** Web App executing as the owner, accessible anonymously. The public status GET discloses no configuration; every POST requires a fresh signed envelope. Configure only the trusted Worker with the Web App `/exec` endpoint and the matching secret. Guests use the Worker, never this bridge or Google authentication. Use separate versioned keys and owner-only roots for TEST and LIVE. The same owner project can serve both bindings. Set `RECEIPTS_KEY_ID=receipt-live-v1` on the LIVE Worker, and `RECEIPTS_ROOT_ID_LIVE` and `RECEIPTS_HMAC_SECRET_LIVE` in Script Properties. LIVE retention is independent of TEST. Never put an initialization function containing a key in a published version.

`v=1`, `keyId=receipt-v1`, ISO timestamp within five minutes, nonce UUID, operation UUID, operation and UTF-8 JSON payload encoded as base64 are signed with lowercase hex HMAC-SHA256 over newline-separated `[v1,keyId,timestamp,nonce,operationId,operation,payloadB64]`. Response signs `[operationId,operation,payloadB64]`. The Worker verifies that signature and the exact file/hash/size/private proof. Receipt bytes have a 2 MiB limit; the nested base64 envelope has a separate 4 MiB bound.

`store` reserves one generated Drive file ID in a private journal before media mutation. `ScriptLock` protects folder and journal updates. Separate receipts can upload concurrently after reservation. Drive creates the file and uploads its bytes in one request. The response or a fresh read must prove the reserved ID, MIME type, size, SHA-256, parent and owner-only permissions before confirmation. Replays reuse that file ID. [Drive upload and retry contract](https://developers.google.com/workspace/drive/api/guides/manage-uploads)

For repeat receipts at the same event or on the same regular booth day, the script uses cached folder IDs to check the root, journal location and all destination levels in one parallel batch with the Drive ID reservation. Each upload gets fresh uniqueness, parent and owner-only checks. The Drive journal records the immutable reservation. The Worker durably records the signed storage confirmation after the exact image is verified in Drive. `read` checks the journal, parent, ACL, Drive checksums and current bytes. Keep this proof-based read path in rollback deployments so it can open receipts from journals created without a confirmation timestamp. No operation sets sharing permissions. Changed permissions fail closed, including on the root and journals. [Drive file metadata and permissions](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)

The signed `ready` operation verifies that the configured owner-private root is a Drive folder that can receive files. It performs only reads. The Payments Worker combines that check with the authenticated original checkout before the iPad displays required-receipt payment instructions. Each actual upload still needs its own storage proof.

`retention` establishes explicitly approved 1–3650 days. No cleanup trigger is created. `trash` also requires explicit approval, matching original identity and eligible age; it moves only that image to recoverable Trash, retaining its journal. A lost response can be retried without permanently deleting anything. The Worker independently checks the account's established period, records actor/reason and preserves the association/storage proof. Normal guest capabilities cannot read or trash receipts.

Run bridge contract checks with `node --test Backend/ReceiptStorage/test/*.test.mjs`.
