# QR gallery redesign evidence

Chrome full-page screenshots of HTML generated by `Code.gs`, reviewed at 320, 375, 390, 430, 768, 1024 and 1440 CSS pixels. Images are synthetic gradients from the existing fixture generator; these files contain no customer photographs or live gallery tokens.

The desktop editorial layout follows the approved reference: compact wordmark/header, left-aligned serif hero, two dynamic Polaroids, two gallery columns, visible color/thermal receipt cards, Instagram card, information strip and footer. Mobile uses a menu, overlapping hero photographs and one gallery column. Receipt cards remain paired at 400px and above and stack below 400px for readable copy. Original gallery photographs display without cropping; their proportions determine page height. Fonts use the browser's local system fonts, so this is not a pixel-perfect reproduction.

`GalleryBrowserLayoutTests` is in `PocketPixelsBoothTests/EventFinalizationTests.swift`. It covers six photo counts at nine viewports, native-share/download fallbacks, original filenames/MIME types, actual image bindings, legacy receipts, menu interaction, gallery link sharing/copying with the token, lightbox navigation/focus, and an intercepted Instagram navigation with no Referer header. Chrome evidence supplements WebKit's DOM/interaction checks.
