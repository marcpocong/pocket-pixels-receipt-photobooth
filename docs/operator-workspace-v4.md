## Design and navigation

The five everyday destinations are **Home, Booth, Sessions, Events, Reports**. Portrait starts with a compact header and a bottom destination bar. The bar is a layout sibling of the content stack, so Booth's Save inset remains above it. Deep typed routes and the selected portrait session have their own Back control and omit the bottom bar. On sufficiently wide landscape windows, the same destinations appear in a 176-point sidebar. The size rule uses available window dimensions, not a device name or orientation notification.

A single `NavigationStack` and lifecycle controller remain in the same structural location when the sidebar appears. System and Help & Recovery are utility shortcuts in the header. Return to Booth retains its existing preflight/printing gates and checkpoints the workspace. Main selection, section paths, report scope and event/payment drafts retain their existing JSON storage. `system` stays decodable as a utility destination. A legacy `recentSessions` root migrates to Sessions, and `regularBooth` migrates to Booth; deeper routes and unrelated saved section paths remain. Old sales/equipment migrations continue to work. The schema version and existing keys remain compatible; the new Regular Booth draft field is optional.

The existing ivory/burgundy `OperatorPalette`, system typography, native lists/forms, status pills, metric layout and confirmation controls form the design system. The session row, thumbnail view/cache, settings Save bar and adaptive detail layout are small focused components. No UI framework or dependency was added. Navigation chrome caps Dynamic Type at XXX Large to keep all five visible labels legible; content, forms, status descriptions and actions continue to support accessibility sizes. Controls have at least a 44-point target. Accessibility labels, selected traits and stable identifiers cover primary navigation and utilities.

Home starts with the authoritative lifecycle/admission status and a separately stated equipment check result. A printer connection alone never produces a ready claim. Two-column portrait quick actions lead to Booth defaults, Sessions, event setup and recovery; accessibility text uses one column. Outstanding parked payments have a separate follow-up entry. Equipment diagnostics and trustworthy event-run metrics follow. Timing/design details live in the event-controls disclosure rather than dominating the summary.

## Everyday workflows

- **Booth:** printing, formats, Receipt & Footer, gallery appearance and advanced device defaults are directly available without starting an event. Receipt & Footer is a typed focused route with a Save bar. The target is explicitly the next Regular Booth guest. The frozen guest configuration and saved/active event designs remain separate. Unsaved copy/format/profile edits checkpoint into an optional workspace draft, appear in Saved Drafts, and restore after tab changes or relaunch. Returning from the footer editor reloads that draft rather than saving stale values from the parent form. Failed draft persistence/discard remains visible. Save feedback follows the existing validated settings write.
- **Sessions:** compact full-width rows use one preview, time, event/Regular Booth, format and concise print/gallery evidence. A photo grid is optional. A full filter form provides Today, date range, event, format and attention filters. No filter requires finding the end of a horizontal chip strip. The model owns search, filters, selection and observed list/grid scroll positions; returning from detail restores context. Portrait opens a full-width detail; wide landscape can retain a list beside it. Original receipt, photo previews, original gallery/QR, explicit operator reprint and collapsed technical details remain available. Existing archive payloads contain photo thumbnails, not an additional full-resolution original-photo collection; those previews are honestly retained as stored.
- **Events:** retains all four validated stages (Event Details, Payment & Prints, Receipt & Branding, Review & Start). A compact progress indicator and stage menu replace a wide stage strip. Save Draft remains separate from Continue and activation. Existing idempotency, authorization, server versions, payment review and occurrence/lifecycle operations remain in their original owners.
- **Reports:** Overview, Sessions, Printing, Galleries, Sales and History are available through a native section menu suitable for portrait. Printing separates original delivered/uncertain/never-started outcomes from explicit operator reprints. Galleries uses recorded verification. Sales retains confirmed LIVE/TEST, operator cash, offline declarations, unresolved/review and unmatched evidence distinctions. A one-column metric layout is available when width or text size requires it.
- **System/Recovery:** device, connection, storage, maintenance and advanced groups preserve the existing destinations. Emergency recovery is always in the header. Close Session & Continue and original-guest payment resume remain the existing production flows.

## Session loading and performance

The baseline eagerly read and decoded up to three thumbnails per archive, retained compressed Data plus decoded UIImages in published dictionaries, scanned all audit rows for every session and performed gallery session file reads during presentation. Source inspection alone was not treated as proof of an FPS cause.

The browser now:

1. Reads metadata off the main actor, immediately publishes it, and skips payload-size directory walks for browsing. Storage/accounting callers still default to complete size calculation.
2. Starts cancellable image tasks for instantiated lazy rows. ImageIO downsamples to at most 256 pixels off the main actor. Each row owns its image completion; there is no published image dictionary or retained raw-data collection.
3. Uses an actor cache with a **12 MiB decoded-byte limit and 96-entry ceiling**, least-recently-used eviction, cancellation checks and memory-warning eviction. A generation prevents in-flight work repopulating a just-cleared cache. Visible UIImages are separate from this disposable cache.
4. Groups audit records by session once per audit update. Pending galleries use keyed lookup; verified journal sessions are loaded off the main actor after journal revisions. Rows compare value snapshots and do not observe the global operational model.
5. Stores filtered/grouped presentations instead of recomputing them in every row body. Refresh cancellation prevents older loads overwriting newer results. Individual reprint bookkeeping reads one archive's metadata without rescanning all archives or evicting thumbnails. Raster bytes and gallery URLs are unchanged.

Benchmarks create independent synthetic archives under temporary test directories; no customer archive is pruned or modified. The original loader and new loader use the same 50/250/500/1,000 fixture sequence. Timing is wall-clock XCTest evidence from the iOS 26.5 simulator on this Mac, with ordinary OS/filesystem caching; it is not a controlled cold-disk study or physical-iPad result. Baseline values: **113.66 / 518.55 / 976.60 / 1,949.76 ms** to show metadata. Original filter/group queries averaged **0.123 / 0.639 / 1.219 / 2.401 ms** respectively. The final measured values, first preview latency, cache bounds, process footprint and scroll callback sample are in `performance-final.json` and `scroll-final.json` in the evidence directory. Process footprint includes the XCTest host and prior work, not just this cache; no baseline process-footprint reduction is claimed.

A four-second CADisplayLink sample advances a real SwiftUI ScrollView programmatically with 1,000 metadata records. It records callback intervals and >34 ms gaps, not sensor-confirmed FPS, Instruments animation-hitch metrics or human finger-scroll performance. Return/resize is exercised in the same hosted window. Search correctness, date/event/format filters, cancellation, concurrent cache readers, cache bounds, memory warning, incremental reprint metadata and storage failures have focused regressions. Production performance on Carlo, native touch scrolling and Instruments allocation/time-profiler traces remain physical acceptance items.

Additional profiler evidence is retained in [performance-results.md](../BuildArtifacts/OperatorWorkspaceV4/performance-results.md), `instruments-summary.json` and the raw trace ZIP. A 16.63-second simulator Time Profiler recording captured 7,013 CPU samples; 201 ImageIO thumbnail-creation samples were all off the main thread. It recorded nine screenshot/attachment microhangs and a temporary-fixture-cleanup hang, which are not concealed or presented as production scrolling costs. The recording warned about one table without a known input source; exported time-profile and potential-hang data are retained. Physical Instruments acceptance remains required.

## Scroll restoration regression found during acceptance

The first strengthened return-from-detail test failed: the browser scrolled to 5,760 points but returned at 44.5 points after detail and rotation. Its optional grouped-layout scroll ID was nil, so selection preservation alone had hidden a real position bug. The return-offset assertion remains unchanged (within 200 points); it was not relaxed to hide the failure.

The fix uses iOS 18's native `ScrollPosition` plus `onScrollGeometryChange`. Real offsets are retained without publishing every scroll update through the archive model. Portrait detail captures a return offset; a visible landscape list keeps its independent browsing position. List/grid have separate offsets, and a recreated primary view initializes its native position from the retained value. The obsolete grouped-ID precondition was replaced with a real observed-offset precondition. The steady final regression returned **5,736 → 5,736 points**, while retaining selection and filters across both rotations. A separate assertion destroys and recreates the hosting/scroll view and again restores **5,736 → 5,736 points**, covering section re-entry rather than merely retaining an already-mounted view. Before/after result summaries and the measured offsets are in the evidence directory. One earlier interrupted/long-running capture is retained only as functional history, not used for performance comparisons.
