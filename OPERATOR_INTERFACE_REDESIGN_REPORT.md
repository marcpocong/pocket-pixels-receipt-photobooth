## Experience and behavior

The previous interface split branding, local charging, server event editing and activation across several screens. Its charging picker immediately persisted mode changes, and customer startup incorrectly required an active, valid local prepaid configuration before resolving paid mode.

- **Operator home:** a neutral iPad layout with booth/event status, price/copies/payment methods, printer status, actionable recovery and a prominent Session Setup action. Prepared paid settings are labeled as unapplied when no event is active.
- **Navigation:** Session Setup, Branding & Design, Sales & History, Equipment and Advanced. Technical pairing, ledgers, recovery, diagnostics and maintenance remain accessible. Closing/archiving events remains under Advanced. Legacy charging/event routes lead to unified setup; sales pages do not edit or discard setup drafts.
- **Session Setup:** two staged choices, Prepaid / Free and Pay Per Print. Copy limits, formats, event selection/creation and branding are edited in one workflow. A persistent Review Setup action opens a concise summary and explicit Start Accepting Guests confirmation. Save Setup Without Starting retains the existing server-draft workflow without publication.
- **Prepaid / Free:** retains saved local values, optional name, included/default copies, maximum copies and the prepaid guest-copy-choice option. Activation publishes a local prepaid policy and uses the existing camera authorization path without PayMongo. Once running prepaid, the Worker is unnecessary. Switching away from an active paid mode requires confirming the remote event is paused; an unavailable server blocks that transition safely.
- **Pay Per Print:** uses the existing authenticated event APIs and published policy. Price/default/max copies, QR Ph, formats, name and venue remain editable; copy range stays **1–10**. Guest-declared cash is explicitly unverified and moved with signed offline cash into Advanced Payment Options. Total previews update from entered prices. The existing `photoPass` server spelling is preserved and mapped to the native Photo Pass renderer rather than silently dropping the sixth format.
- **Safe transitions:** mode selection never changes booth operation. A durable barrier closes before activation. Exact saved policy and price are acknowledged, the selected active event is reread, and only then is the committed mode opened for guests. Mode and acceptance are stored atomically to avoid a delayed preferences-write restart race. Unknown outcomes trigger read-only status recovery, retain drafts and require another explicit review; mutations are never automatically repeated. Active sessions and unresolved recovery block switching. Pause stops new sessions while preserving fulfillment and reconciliation. Another unexpectedly active event is not silently paused or adopted.
- **Branding:** studio/custom/current design choices work with either payment mode. Artwork and design settings are reused, not duplicated or erased. Event Mode wording is replaced with Apply Custom Branding / Use Studio Branding.
- **Persistence and gating:** optional additions to the existing workspace snapshot preserve older files and routes. Mode choices and separate prepaid/paid drafts survive relaunch with exact server binding and version-conflict review. Authentication and the concealed native privacy cover remain intact. Prepaid readiness is now checked only in the prepaid branch; paid mode resolves its server policy independently. Operator-armed paid recovery remains ahead of the new-session barrier.
